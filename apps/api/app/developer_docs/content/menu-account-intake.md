## 页面用途

接入记录用于审计访客从推广渠道发起的首次绑定或已有账号重新认证过程。它关注“一次接入尝试”，而不是只展示最终账号。

## 主要字段

| 字段 | 说明 |
| --- | --- |
| 号码 / 账号 | 用户提交号码和最终关联的账号 ID |
| 号码国家 | 服务端根据 E.164 号码识别的国家，不使用渠道或访问国家代替 |
| 接入类型 | 首次接入或重新认证 |
| 接入状态 | 配对码发出、等待手机、重连、成功、失败、过期或取消 |
| 入池结果 | 账号是否正式进入统一账号池 |
| 渠道 | 发起该尝试的推广渠道 |
| 协议 / 分组 | 本次尝试快照的路由和目标分组 |
| 资料同步 | 成功接入后的后台同步状态 |
| 发起时间 | 本次接入尝试创建时间 |

## 如何判断成功

配对只有在 `pairingStatus=verified` 且 `verified=true` 时才算成功。账号连接显示为离线并不等于配对失败；验证完成后资料同步可能继续处于 `syncing`。

失败、过期和取消属于接入尝试的终态，不会因为刷新页面自动重新开始。用户应从原渠道重新发起。

## 功能边界

- 记录页用于审计，不提供手工修改接入结果；
- 一次失败尝试不等于账号池中一定存在可用账号；
- 资料同步失败应在账号管理或协议配置中处理，不能在此页改写状态；
- 页面不会展示配对状态令牌、会话 JSON 或其他敏感凭据。
