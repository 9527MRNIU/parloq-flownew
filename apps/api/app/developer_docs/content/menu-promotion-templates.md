## 页面用途

模板管理负责保存推广落地页的静态 ZIP 包，并控制模板版本、可用状态和管理端预览。模板是渠道的页面资源；渠道域名、账号分组和协议路由不在此页配置。

## 列表字段

| 字段 | 说明 |
| --- | --- |
| 模板 | 模板名称、系统 ID 和当前可用状态 |
| 版本 | `manifest.json` 中声明的模板版本 |
| 语言 | 默认语言和支持的语言数量 |
| 资源 | ZIP 解包后的文件数量 |
| 使用渠道 | 当前引用该模板的渠道数量 |
| 更新时间 | 最近一次导入版本或更新状态的时间 |

## 可执行操作

- **导入模板**：上传符合规范的 ZIP；包内有名称和说明时自动填写，也可在导入前手动修改；
- **模拟预览**：切换设备和语言查看页面效果，预览不会创建账号或占用 IP；
- **替换版本**：为同一模板导入新的 ZIP 版本；
- **启用 / 停用**：控制模板是否继续作为可用模板参与配置；
- **设计规范**：查看并复制 v2 设计要求，或下载白标能力主题；
- **模板策略**：管理设备信号、检查保护和公开数据回传限速等平台级运行策略。

新建和修改操作需要 `promotion.templates.manage`，只读角色只能查看和预览。

## 导入边界

系统只接受自包含 ZIP。必须有唯一的 `index.html` 和有效 `manifest.json`，入口不能改为其他文件。当前限制为：ZIP 最大 20 MB、解压后最大 50 MB、单文件最大 5 MB、文件数最多 500 个。

新模板应使用 `promotion-template/v2`。v1 只保留兼容用途，不应作为新项目起点。

## 数据回传限速

“模板策略”提供四组租户级默认额度：单会话数据回传、同一 IP 数据回传、单渠道回传总量和 Facebook 域名异常回传。每组都配置“最多请求”和“统计窗口（秒）”。这些额度只保护公开事件写入，不占用协议节点中的配对、状态查询或取消请求额度。

主模板与每个 iframe 集成分别计数，同一渠道下的不同 iframe 集成也互不消耗额度。Facebook 域名异常回传按域名和请求来源单独计数。达到额度时公开接口返回 `429` 和 `Retry-After`；Redis 暂时不可用时保留事件写入能力并记录服务端告警，避免统计组件故障阻断落地页主流程。

## 功能边界

- 页面不提供在线源码编辑器；修改源文件后应重新构建并导入版本；
- 模板不决定公开域名、短码、账号来源或协议节点，这些属于渠道配置；
- 管理端预览只验证视觉和交互流程，不等同于真实渠道验收；
- 被渠道引用的模板不能直接删除，应先处理引用关系；删除后模板及其本地资源无法恢复。
