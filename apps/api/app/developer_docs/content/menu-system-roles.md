## 页面用途

角色管理把一组菜单访问范围和新增、编辑、购买、导入、导出等操作权限组合起来，再分配给用户。该页面只对管理员开放。

## 两类权限

### 菜单权限

菜单权限决定用户能看到哪些导航入口，以及能否读取相应资源。选择子菜单时，系统会同时保留必要的父级目录，确保导航结构完整。

### 操作权限

操作权限决定用户是否可以对资源执行写入行为。例如拥有“模板管理”菜单并不自动拥有“导入模板”按钮；还需要对应管理权限。

## 可执行操作

- 创建自定义角色；
- 设置名称和用途说明；
- 选择可访问菜单；
- 选择可执行操作；
- 查看角色成员数和权限数量；
- 编辑或删除未受保护的自定义角色。

## 内置角色

管理员和普通用户属于内置角色。管理员权限由系统保持完整，内置角色受到删除和关键字段修改保护。自定义角色应按最小权限原则建立。

## 功能边界

- 角色不保存业务数据归属，只定义访问能力；
- 删除仍有用户的角色会被拒绝或需要先迁移成员；
- 菜单可见不代表拥有写操作，操作权限也不能绕过缺失的菜单读取权限；
- 修改角色会影响该角色下所有用户，应在保存前确认成员范围。
