## 导入前自检

- `manifest.json` 为 v2 且字段与构建产物一致；
- ZIP 根目录包含唯一 `index.html`，资源全部使用相对路径；
- 不包含 Source Map、外部脚本、协议节点 ID、网关地址或访问令牌；
- 不在本地存储、Cookie、URL 或日志中持久化手机号；
- 所有状态和取消请求都通过 v2 Bridge；
- 每个声明 locale 都有完整文案和可用回退。

## 管理端模拟预览

模拟预览应完成输入、提交、配对码、等待、验证成功和初始化状态展示。预览不会创建真实账号或占用 IP，因此只能作为视觉和基础交互验收。

需要检查的视口至少包括：

| 视口 | 重点 |
| --- | --- |
| 360 × 800 | 小屏手机、键盘弹起后的表单空间 |
| 390 × 844 | 主流手机布局与按钮可触达性 |
| 768 × 1024 | 平板双向布局和内容宽度 |
| 1440 × 900 | 桌面留白和最大内容宽度 |

所有视口都不能出现非预期横向滚动、遮挡或不可触达操作。

## 真实渠道验收

在隔离测试渠道和测试账号上验证：

1. `waiting_phone` 的正常等待；
2. `reconnecting` 的恢复提示与继续轮询；
3. `verified` 且 `verified=true` 的成功判断；
4. `failed`、`expired`、`cancelled` 的终态和重新开始；
5. 用户主动取消；
6. 初始化 `pending → syncing → ready`；
7. 应用无法拉起时的手工步骤；
8. 自动语言、手工切换和 RTL。

## 安全边界

- 模板不得自行调用网关或保存配对鉴权信息；
- 模板不得暴露 Parloq 控制面品牌、内部 ID 或基础设施地址；
- 模板不得加载自己的统计 SDK；渠道营销事件由平台统一配置和去重；
- 页面检查保护由平台运行时执行，模板只展示被阻止时的中性说明；
- 生产验收使用一次性测试账号和受控代理，不使用重要个人账号。

## 发布结论

只有 ZIP 校验、管理端预览、真实渠道全状态、多语言与安全检查全部通过，模板才应绑定正式渠道。任何契约不确定项都应回到当前文档和系统生成的“接口规范”核对，不要根据旧模板猜测。
