## 页面用途

渠道管理把模板、域名、账号分组和协议路由组合成一个可访问的推广入口。每个渠道拥有独立短码、投放国家和营销追踪配置；新建渠道默认面向全球，也可以收窄到单个国家或地区。

## 核心配置

| 配置 | 作用 |
| --- | --- |
| 模板 | 决定落地页的静态页面和运行时能力 |
| 账号分组 | 成功接入后的账号归属和后续调度范围 |
| 协议节点 / 协议池 | 决定新接入请求走哪条配对线路 |
| 域名、子域前缀、短码 | 组合公开访问地址 |
| 投放国家 | 渠道统计和运营识别使用的投放范围；全球使用地球图标展示 |
| 语言 | 根据投放国家、浏览器语言和模板默认语言自动解析 |
| 渠道状态 | 控制渠道是否可以接收新访问 |

协议池按配置顺序选择首个可接入且未超容量的节点。修改渠道路由只影响之后的新接入，不迁移已经存在的账号。

## 营销追踪

渠道可以绑定 Meta 数据集；浏览器像素、CAPI 投递和事件映射统一在 Pixel 管理中配置。应用内浏览器处理方式和新账号营销开关在渠道内配置。只有绑定有效数据集后，相应投递能力才会生效。

渠道洞察可以查看访问、号码提交、接入结果、线索列表、广告日数据和 Meta 投递汇总。广告花费、展示和点击属于人工录入的日指标，可在有统计管理权限时维护。

## 常用操作

- 新建或编辑渠道并生成访问地址；
- 复制公开访问地址；
- 启用或暂停渠道；
- 选择渠道查看洞察与线索；
- 维护 Meta 数据集配置和每日广告指标。

## 功能边界

- 渠道不保存模板源码，只引用已导入模板；
- 渠道不直接拥有账号凭据，只绑定账号分组；
- 暂停渠道不会自动断开已经接入的账号；
- 更换协议路由不会迁移历史账号；
- 渠道公开地址只有在域名 DNS、TLS 和托管状态就绪后才可正常使用。
