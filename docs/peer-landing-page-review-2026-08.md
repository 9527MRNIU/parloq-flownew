# 同行推广落地页前端观察

观察对象：[公开推广页](https://c.ttsmi66.xyz/ig4c3nkr)

观察时间：2026-08-13。本文只总结可复用的产品和工程模式，不复制页面素材、文案或代码。

## 值得学习

- 移动端优先：整屏主视觉、单一 CTA、号码输入与国家区号组合，关键内容在一屏内完成。
- 转化层次清楚：社会证明、价值主张、信任提示、号码输入和 CTA 顺序明确。
- CTA 有有效性门槛，号码不完整时保持禁用，减少无效请求。
- 国家能力：页面会做国家探测，并提供区号选择，不要求用户自己输入完整国际格式。
- 配对不是一次请求：实现了获取配对码、倒计时、状态查询、已占用、失败、重试和成功等状态。
- 会话连续性：保存页面进度，并在可见性变化和离开页面时处理统计或连接状态。
- 资源优化：字体预连接、图片域 DNS 预取、CSS preload、图片懒加载、移动端固定视口布局。
- 多语言：页面根据环境自动切换语言，主要 UI 文案能够动态翻译。

## 它的“反调试”实际做了什么

公开产物使用了代码压缩/混淆和 DevTools 检测组件。生产页会拦截右键、F12、查看源码及常见开发者工具快捷键；检测到开发者工具后会清理控制台并离开当前页面。

这属于增加分析成本，不是安全措施：HTML、CSS 和 JavaScript 仍然已经下载到浏览器，资源地址也仍可直接请求。强制检测还可能误伤停靠开发者工具、无障碍工具或某些浏览器环境。

Parloq 采用更稳妥的边界：生产渠道页由平台统一禁右键和常见快捷键，模板构建关闭 source map；不做高频 DevTools 探测和强制跳空白页。真正敏感的协议凭据、密钥和鉴权逻辑不进入前端。

## 隐藏 iframe 的实际作用与风险

页面末尾的零尺寸 iframe 并非普通占位元素。它加载的独立域代码会：

- 用 User-Agent、语言和屏幕尺寸生成设备指纹；
- 上报固定渠道码、设备版本、访问来源和门页域名；
- 首次延迟上报后每 20 秒继续向 `/api/v1/ip-sync` 发送；
- 根据 iOS 版本选择不同加载器，其中新版本文件和 Worker 明确使用 `rce` 命名，并运行设备能力探测代码。

因此它至少用于跨域设备/IP 同步、渠道关联和环境筛选；从公开代码命名和 Worker 行为看，还存在面向特定设备投递利用链的明显风险。后者是基于公开产物的安全推断，不能只把它理解成统计 Pixel。Parloq 不引入这种隐藏跨域执行能力。

## 不应照搬

- 页面包含上述不可见外部 iframe；它的数据采集和设备代码均超出正常推广模板边界。
- 页面主 JavaScript 体积较大，且把业务、翻译、图片和防调试能力集中在一个包内；我们应拆分并设置体积预算。
- 禁止页面缩放会损害无障碍体验；我们只限制布局，不禁止用户缩放。
- 动态人数、身份验证、安全承诺等文案如果没有真实数据支持，不应展示。
- 模板不应自己接第三方统计或把号码发送到外部；这些能力应由平台统一管理和审计。

## 对 Parloq v1 的落地

- 建立 `parloq-promotion-template/v1` ZIP 和 manifest 规范。
- 平台提供统一 `parloqSubmitPhone` 浏览器桥接。
- 后台预览使用无副作用的模拟配对流程。
- 真实渠道页统一注入事件追踪、Baileys 配对、Pixel 和交互保护。
- 模板自包含、无外部 JavaScript、无隐藏 iframe、无 source map。
- 验收覆盖移动端、加载/错误/成功状态、多语言、RTL、无障碍和性能预算。
