# 代理健康升级方案

## 目标

- 导入代理后立即做一次真实检测。
- 后续不定时轮询，由网关实际使用结果回写。
- 连续失败达到阈值后进入冷却。
- 冷却作为现有分配模式的公共过滤条件，不改四种模式本身。

## 规则

| 场景 | 处理 |
| --- | --- |
| 批量导入 | 网关携带真实协议和凭证访问 WhatsApp Web |
| 网关连接成功 | 标记健康，连续失败清零 |
| 普通代理连接失败 | 连续失败达到策略阈值后进入冷却 |
| 代理认证或配置失败 | 立即隔离，修改配置或手动复检后恢复 |
| 冷却期间 | 不参与严格 1:1、租户内复用、低负载优先或手动绑定 |
| 冷却到期 | 以最低优先级重新试用，成功恢复健康 |
| 已绑定账号 | 不自动更换固定代理；断开但保留会话，任务换健康账号 |

健康状态仍只有 `untested`、`healthy`、`unhealthy`。冷却是
`unhealthy` 上的时间属性，不新增状态。

## 国家匹配

- 访问国家：公开落地页按访客访问国家匹配；拿不到时回退号码国家。
- 号码国家：按账号 E.164 号码识别的国家匹配。

国家只决定优先匹配来源，不改变四种分配模式的容量、租户隔离和手动语义。

## 明确不做

- 不做后台定时巡检。
- 不做健康评分或复杂多状态模型。
- 不自动更换已配对账号的固定代理。
