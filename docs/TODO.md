## 推广管理

### App 内置浏览器外部打开

- 状态：`待实施`
- 优先级：`P2`
- 记录日期：2026-08-24
- 关联模块：渠道管理、推广页面运行时、推广模板

背景：渠道目前通过 `inAppBrowserMode` 区分 `allow` 和
`guide_external`。运行时仅根据 User-Agent 中的 `FBAN`、`FBAV` 或
`Instagram` 识别 Facebook / Instagram 内置浏览器，并发送
`promotion:in-app-browser` 事件。生产环境现有模板没有监听该事件，因此
`guide_external` 目前不会向访问者展示实际引导。

目标：让渠道的“App内打开”配置形成完整、跨模板一致的访问者体验，同时不把
受系统和宿主 App 限制的外部拉起能力描述为百分之百强制跳转。

实施要点：

- [ ] 重新确认开关名称和说明，使“允许在 App 内继续访问”与“引导使用系统浏览器”的语义清晰；
- [ ] 由平台运行时提供最小、白标、中性的统一引导层，现有模板无需单独接入；
- [ ] `allow` 模式保持现有流程，`guide_external` 仅在明确识别受支持的内置浏览器时展示引导；
- [ ] Android 在用户主动点击后使用 `intent://` 尝试把完整 HTTPS 地址交给外部浏览器，并保留失败后的手动说明；
- [ ] Android 优先尊重系统可用浏览器，不把 Chrome 作为唯一依赖；
- [ ] iOS / iPadOS 不使用私有 Safari Scheme，不承诺自动跳出，只提供与宿主 App 对应的手动操作说明；
- [ ] 保留完整 path、query 和 hash，避免丢失渠道归因参数；
- [ ] 第一版继续覆盖 Facebook 与 Instagram，其他 WebView 在取得真实业务需求和真机样本后再加入；
- [ ] 保留 `promotion:in-app-browser` 事件，供模板做样式增强或监控扩展；
- [ ] 增加“引导已展示”“尝试外部打开”“继续 App 内访问”等必要监控，不记录敏感参数；
- [ ] 增加运行时、模板渲染和真机测试，覆盖普通浏览器、未知 WebView、重复进入与前后台切换。

验收条件：

- 普通 Safari、Chrome 等浏览器不展示内置浏览器引导；
- `allow` 模式下，Facebook / Instagram 内置浏览器可以正常继续流程；
- `guide_external` 模式下，Android 提供用户点击触发的外部浏览器尝试和手动后备说明；
- `guide_external` 模式下，iOS 提供准确的手动外部打开说明；
- 外部打开前后的完整地址和归因参数一致；
- 跳转失败不会产生白屏、循环跳转或阻断账号关联；
- 所有现有模板无需单独添加事件监听即可获得基础引导能力。

明确不做：

- 页面加载后自动发起外部跳转；
- 隐藏 iframe、定时器跳转或未公开的 iOS URL Scheme；
- 为未验证的 WebView 建立宽泛 User-Agent 规则；
- 因该功能改变账号关联、协议路由或服务端配对语义。
